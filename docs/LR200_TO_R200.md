# LR200 → R200：有效流程与证据

## 已验证有效

1. 使用 librealsense legacy 的 DS4 `download_spi_flash (0x1A)` 连续读取两份 1 MiB Flash。
2. 补丁官方 `FWUpdateR200.exe` 的 4 处 PID 和 3 个完整 UVC 节点名，使它能匹配 LR200。
3. 以 `-n -force -confirmed` 运行补丁版更新器：只更新主固件，暂时不写 IFFLEY/NV。
4. 从正常 R200 只读取得 admin root 和 NV 布局证据；供体全程禁止写入。
5. 建立 R200 root、校准和 IFFLEY 所需记录后，Depth/IR 恢复出帧。
6. 所有 NV 写入都采用单 sector 擦写、逐页写入、立即回读校验。

历史命令形态：

```powershell
FWUpdateLR200-full-match.exe -n -force -confirmed
```

不要直接复制该命令运行。必须先核对官方更新器 SHA-256、设备 PID/节点名、双份 Flash 备份和回滚路径。

## 布局差异

R200 `0xA0000` root 的 9 个 little-endian uint32 指向 admin records。典型值包括：

```text
index 0 -> 0xA1000  calibration + camera head
index 1 -> 0xA2000
index 2 -> 0xA3000
index 3 -> 0xA4000
index 7 -> 0xA6000
index 8 -> 0xA7000
```

LR200 对应 payload 通常从每 sector `+0x2D` 开始。R200 payload 从 `+0` 开始并在末尾保留 slot metadata。转换时要复制 payload，不要覆盖 R200 trailer。

## 当前 RGB 故障

同一台主机、同一 `1920×1080 YUYV@30` profile：

- 正常 R200：连续出帧，streaming status 出现 RGB intent 位。
- 转换目标机：UVC `start()` 成功，第一帧超时；XU SET/GET 正常，但 status 长期多出 `0x08`。

A1 旧标定未修复 RGB。A3 旧配置候选会进一步产生 `0x10` 状态并影响 Depth，已回滚。当前更强的候选是主/备用固件对 LR200 RGB sensor revision 的初始化差异，而不是一个尚未复制的普通内参表。

## 回到 LR200 的限制

原始 `2.0.71.04` 仍保存在写前全片备份中，但它不是可直接交给 FWUpdate 的 IHEX。公开 opcode 写固件区会返回设备端拒绝状态；非固件 NV 可写不代表主/备用固件 bank 可用同一路径改写。
