# F250 → SR300：有效流程与剩余问题

## Recovery 进入方式

F250 PCB 上的 SW1 是松手回弹按钮。实测可通过按住 SW1 上电数秒，使设备以 Front F200 / PID `0A95` 枚举；它对 F250 的 recovery 进入有实际作用。

普通拔插后必须等待完整枚举。设备可能先只出现控制节点，随后才恢复 RGB、Depth 相机节点，过早判断会误以为枚举失败。

## 固件链

本地验证过的 SR300 固件阶段包括：

- F250 原厂运行态：`3.2.22.0`
- SR300 过渡：`3.10.10.0`
- SR300：`3.15.0.0`
- 后续包：`3.21.0.0`、`3.26.1.0`

关键问题不是“Viewer 太新”，而是 F250 与 SR300 的版本、序列号和标定表地址/结构不同。SR300 firmware/SDK 查询 F250 Flash 中不存在的参数表 ID 时会返回：

```text
Params table id not valid (-17)
```

## 当前结果

- SR300 PID 和三个设备节点可以正常枚举。
- RGB 可以在 librealsense 2.29/2.54 路径出帧并运行屏幕延迟测试。
- Depth/IR 无帧；仅绕过 SDK 参数表检查不能修复固件内部深度初始化。

因此“能枚举为 SR300”与“完整转换为量产 SR300”必须分开描述。
